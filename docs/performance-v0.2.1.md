# Folio v0.2.1：浮动 AI 拖动性能实测

最终 Mac universal 包完成一次 77.35 秒复测。持续拖动磨砂 AI 窗时，CPU 均值为 **31.938%**；松手后的连续 8 秒降至 **0.481%**，面板样式变化次数为 **0**，未观察到拖动结束后继续刷新的现象。这里 **100% 表示占满一个逻辑核心**，不是整机 CPU 百分比。

测试时间为 2026-09-21 23:37（北京时间），设备为 Apple M1 Pro、10 个逻辑核心、16 GiB 内存、2× 屏幕缩放。64/64 个采样点全部聚焦且可见，16 次阶段边界检查的系统前台 PID 均属于测试实例。只在开始激活一次，未补抢焦点、复跑或剔除采样。测试实例已退出，运行无错误或警告。

使用隔离文献库的 100 页正文与 40 页补充 PDF，均为密集文字和栅格图夹具，两个阅读窗格保持 100% 缩放。每个滚动阶段移动 16 × 540 = 8640 CSS 像素。拖动阶段以 30 Hz 发送 240 次实际指针移动，持续 8 秒，在阅读区内水平往返并上下移动；随后松手、原地测量 8 秒。未设置 API Key 或调用 AI。

浮层实际启用了 `blur(12px)`。拖动期间记录到 240 次指针移动、480 次面板样式属性修改（横、纵坐标分别写入）；松手后两项均为 0。拖动没有改变 PDF 视窗尺寸、滚动位置、缩放或画布数量；始终保留 20 个已分配画布，共 71,179,680 像素，单画布最大 3,558,984 像素。

首次磨砂静止阶段末尾出现了 16.019% 的单次 CPU 高值，已完整保留，不能将其与后续松手静止阶段混为同一状态，也没有足够证据把它归因于模糊或内存回收。此轮工作集总和约 1.13–1.22 GiB，包含密集双 PDF、缓存与 Electron 多个进程；共享内存可能重复计数，后测阶段数值变化不能直接证明布局节省内存。短测和自动指针采样也不能代替长期稳定性或电池耗电测量。

GPU 一列来自 `ioreg` 的**整机**计数，包含 WindowServer 和其他应用，**不能归因于 Folio**；GPU 进程的 CPU 已计入上面的 CPU 列。
