# Folio 早期渲染优化性能实测

2026-09-21，在 Apple M1 Pro（10 个逻辑核、16 GiB 内存）上顺序运行优化前和优化后的真实 Electron 应用。测试导入 **100 页正文 + 40 页补充材料**，双栏阅读；每页有 98 行文字和一张 1600 × 650 的合成图表。两轮均完成全部 8 个阶段，无脚本或渲染器错误。

**本轮最明显的改善是高倍缩放内存：200% 缩放滚动阶段，各进程工作集之和的峰值从 2,032 MiB 降至 1,036 MiB，下降 49%。** 优化版空库静置平均 CPU 为 0.72%。后续完成了真正前台的打包版补测：双栏静置 CPU 平均 0.45%；200% 缩放滚动结束后，20 秒恢复窗口平均 0.88%，最后 10 个样本平均 0.19%、最高 0.25%。这里 **100% CPU 等于占满一个逻辑核**，与 macOS 活动监视器的常见口径一致。

这些是共享桌面上的一次短时测量。优化版窗口所有样本都可见但未聚焦，基线部分阶段聚焦，因此不能将两轮 CPU 差异全部归因于代码优化；后续独立补测验证了短时前台静置行为，仍不代表续航或长期占用。GPU 只能取得**整机**利用率，不能声称测到了 Folio 独占 GPU 使用率。

## 逐阶段结果

CPU 为应用各进程之和的阶段平均值；括号内是最高约 1 秒采样区间。内存为各进程工作集之和的采样峰值，单位 MiB，共享页可能重复计算，**不等于独占物理内存**。

| 场景 | 基线 CPU 平均（最高） | 优化后 CPU 平均（最高） | 基线峰值内存 | 优化后峰值内存 |
|---|---:|---:|---:|---:|
| 空论文库静置，8 秒 | 0.47%（1.19%） | 0.72%（1.39%） | 473 | 477 |
| 导入并索引 140 页，10 秒窗口 | 16.11%（156.16%） | 16.93%（164.54%） | 746 | 744 |
| 双栏初始页面静置，10 秒 | 1.79%（8.12%） | 1.38%（10.39%） | 732 | 685 |
| 双栏滚动、适合宽度与 100% 切换，约 13 秒 | 28.81%（43.19%） | 29.75%（42.45%） | 1,269 | 1,199 |
| 普通交互后的恢复，27 秒 | 5.52%（17.80%） | 1.38%（13.41%） | 1,261 | 1,173 |
| 双栏 200% 缩放并滚动，8 秒 | 17.39%（53.86%） | 17.38%（31.38%） | 2,032 | 1,036 |
| 200% 缩放后静置，8 秒 | 1.46%（9.01%） | 0.48%（1.06%） | 2,026 | 887 |
| 返回论文库并重开缓存工作区，8 秒窗口 | 21.12%（161.88%） | 9.42%（71.43%） | 1,178 | 802 |

缓存工作区重开阶段平均 CPU 降低 55.4%，首次文字层挂载时间由 0.31 秒变为 0.23 秒；这不代表全部页面绘制完成的时间。初次导入至索引就绪、双栏文字层挂载由 0.67 秒变为 0.88 秒。普通滚动的平均 CPU 没有下降，空库内存仍约 477 MiB；不能把结果描述成各项性能都变好，或声称具有原生轻量阅读器的内存水平。

基线普通恢复阶段末尾 8 个样本平均 CPU 为 15.29%，最高 17.80%，该末段恰好发生重新聚焦；优化版对应阶段始终未聚焦，末尾平均 0.33%。这个差异受焦点和桌面活动影响，**不作为“静置 CPU 降低 98%”的证据**。两轮窗口始终可见。各样本的焦点、可见状态与逐进程数据均保留在原始 JSON 中。

## 打包版前台补测：全部 28 个样本通过焦点验证

桌面停止人工操作后，使用当时的打包版 `Folio.app`、独立临时论文库和相同 140 页 PDF 补测。该测量早于后续共用批注工具栏、已移除文章与 Windows 适配改动，不能视为当前 DMG 的完整性能复测。按测试 PID 原生激活窗口后，每个采样点同时检查 `BrowserWindow.isFocused()` 和 macOS `NSWorkspace` 的前台应用 PID。**初始双栏静置 8/8 个样本、200% 缩放恢复 20/20 个样本都保持真实前台、可见状态；采样过程中没有再次抢焦点。**

| 前台场景 | 聚焦且前台 PID 匹配 | CPU 平均 / 最高 | 工作集平均 / 最高 MiB | 整机 GPU 平均 / 最高 |
|---|---:|---:|---:|---:|
| 双栏初始静置，8 个约 1 秒样本 | 8 / 8 | 0.45% / 1.40% | 739.93 / 740.09 | 0.25% / 2% |
| 200% 缩放滚动后恢复，20 个约 1 秒样本 | 20 / 20 | 0.88% / 9.74% | 806.60 / 1,016.81 | 0.20% / 2% |
| 上述恢复窗口最后 10 个样本 | 10 / 10 | 0.19% / 0.25% | — | — |

初始静置前等待 3 秒；双栏滚动、切换 200% 并再次滚动后等待 5 秒，再开始 20 秒采样。CPU 仍以一个逻辑核为 100%，工作集可能重复统计共享页。9.74% 是恢复窗口中真实出现的短时 CPU 峰值，不省略；最后 10 个样本已回落到 0.17%–0.25%。恢复期间未记录到指针、滚轮、键盘、滚动事件或 DOM 变更。本次未观察到持续的高 CPU 活动。

GPU 列仍是**整机** Apple GPU 利用率，不是 Folio 的独占 GPU 数据。另一个 Folio 实例继续运行；CPU 与内存仅统计隔离测试实例的进程。此次测试不调用 AI，也不是耗电量或长时间内存稳定性测试。

[历史补测脚本](../scripts/performance-focused.mjs)记录逐秒、逐进程数据与焦点状态。原始结果 `test-results/performance-focused.json` 和截图 `test-results/performance-focused.png` 是本地产物，不随源码仓库发布。测试无渲染器错误，所有测试进程退出，另一个 Folio 实例保持运行。该脚本保留当时的包路径与界面定位，运行新版本前需适配；当前阅读布局测量入口见[性能测试说明](../scripts/PERFORMANCE.md)。

### 之前两次失焦尝试的保留记录

之前在共享桌面活动期间的两次尝试均为 0/20 个聚焦样本：Electron 请求激活一轮 CPU 平均 2.26%、峰值 28.20%；按 PID 原生激活一轮平均 1.32%、峰值 13.15%。第二轮原生激活瞬间成功，但等待 5 秒后再次失焦，并记录到 35 次指针移动；不能推断焦点变化的具体来源，也不能把两轮数据作为前台低占用证据。

两次失焦尝试分别记录在本地 `test-results/performance-focused-unfocused-electron.json` 和 `test-results/performance-focused-unfocused-native.json`，不随源码仓库发布。上述摘要保留这些失败尝试；随后在停止人工操作后进行的前台测量单独统计，没有将失焦样本混入前台结果。

## 改动与内存结果的对应关系

PDF 渲染限制单个常规画布的最大像素数，并保留 PDF.js 的局部细节渲染；同时释放离屏缩略图位图。200% 缩放结束时，实测最大画布由 14.24 百万像素降至 3.56 百万像素，所有 PDF 画布像素之和由 160.35 百万降至 32.29 百万，减少 79.9%。这个直接观测支持高倍缩放工作集下降的解释，不需要用系统 GPU 计数推断。

已有全文索引会复用；同一文件多栏共享抽取任务；首次索引以小批次串行运行并让出主线程。窗口尺寸变化合并处理，未改变的批注复用 DOM。这些改动仍保留完整页数、独立翻页、分栏和缩放行为。

阅读助手另行将流式增量合并为约 90 毫秒一次更新，并缓存已完成消息的 Markdown 渲染。无回复时不运行更新定时器；完成、停止及卸载会取消待执行更新并保留最终文本。定时器与末尾文本的回归检查及完整流式对话测试已通过。**本 PDF 性能基准没有调用 AI 服务，未测量真实模型回复时的 CPU 或 GPU，不能给出该项资源下降百分比。**

## GPU 数据的边界

测试每秒读取一次 `ioreg` 的 `AGXAccelerator / PerformanceStatistics / Device Utilization %`。这是整个 Apple GPU 的活动，包含 WindowServer 和其他应用。例：空库阶段整机 GPU 平均值从基线的 0% 变为优化版的 18.38%，而 Folio 此时 CPU 均不足一个核的 1%；这些整机值不能用于计算 Folio 的 GPU 改善比例。

Electron 中名为 `GPU` 的进程也会使用 CPU。优化版普通双栏滚动阶段该进程平均 **CPU** 为 6.40%，并不是“GPU 占用 6.40%”。每个阶段的整机 GPU 数值及 Browser、Tab、GPU、Utility 进程 CPU 和工作集均保存在原始结果中。没有申请提权，也没有获得逐应用 GPU 利用率或功耗数据。
